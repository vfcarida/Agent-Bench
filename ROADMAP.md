# Agent-Bench Architecture & Evolution Roadmap

This document defines the architectural north star, engineering maturity governance, verified capability matrix, and next-horizon research tracks for **Agent-Bench**.

---

## 1. Vision & Architectural North Star

**Agent-Bench** is a multi-domain, safety-gated evaluation framework for tool-augmented and multi-agent AI systems across regulated enterprise verticals (`pix_assist`, `investment_advisor`, `sme_business_advisor`, `cyber_sandbox`).

Its architecture is anchored on six scientific and executive pillars:
1. **Non-Compensable Safety Gating** (*AgentHarm* `arXiv:2410.09024`; *Agent-SafetyBench* `arXiv:2412.14470`; *Gartner AI TRiSM*): Safety or policy violations are never averaged into functional quality scores. Phase 0 safety gates short-circuit execution before deterministic (Phase 1) or calibrated semantic judge (Phase 2) evaluation.
2. **Multi-Trial Reliability (`pass^k` vs. `pass@k`) & Dual-Control Simulation** (*$\tau$-bench* `arXiv:2406.12045`; *$\tau^2$-bench* `arXiv:2506.07982`): High-risk transactional and cybersecurity profiles evaluate worst-case consistency across $k$ trials ($\text{pass}\hat{\ }k = \binom{c}{k}/\binom{n}{k}$) alongside optimistic capability ($\text{pass}@k$), 95% bootstrap confidence intervals, and Dec-POMDP dual-control shared-world user simulation (`DualControlUserSimulator`).
3. **Joint Cost-Quality Pareto Optimization & Graduated Autonomy** (*AI Agents That Matter* `arXiv:2407.01502`; *BCG Graduated Autonomy*): Systems are evaluated on a safety-constrained 2D Pareto frontier (`functional_score` vs. `cost_per_successful_task` with hypervolume indicator) and mapped into deployment readiness tiers (`Tier 1 — Shadow` $\rightarrow$ `Tier 4 — Full Bounded Autonomy`, or `Blocked — Safety Gate Triggered`).
4. **Psychometric & 2PL IRT Fast-Anchor Diagnostics** (*FINESSE-Bench* `arXiv:2605.15482`; *tinyBenchmarks* `arXiv:2402.14992`): Automated run diagnostics compute adjacent-difficulty degradation ($\Delta_{\text{easy}\to\text{expert}}$), cross-domain balanced profiles, cross-family transfer gaps, item-level discriminative power, and 2-Parameter Logistic (2PL) Item Response Theory (`metrics/irt.py`) for fast-anchor subset selection (`--fast-anchor`).
5. **OpenTelemetry GenAI & Model Context Protocol (MCP) Interoperability**: Native OTLP/JSON span export adhering to OpenTelemetry GenAI Semantic Conventions (`gen_ai.*` attributes via `bench export-otel`) and bidirectional JSON-RPC 2.0 MCP tool/resource bridging (`tools/mcp_bridge.py`).
6. **Multi-Agent Byzantine Resilience, Causal Counterfactual Replay & Online Drift Assurance**: Stress-testing multi-agent handoffs against Byzantine faults and collusion (`runners/byzantine_orchestrator.py`), deterministic trajectory forking for causal guardrail attribution (`runners/counterfactual.py`), and continuous shadow-traffic CUSUM / Jensen-Shannon drift monitoring (`runners/online_eval.py`).

## 2. Maturity Tiers & Verification Governance

Every subsystem in Agent-Bench is governed by an explicit, test-verified maturity taxonomy. A component may only advance to a higher tier when all objective quality gates for that tier are satisfied in CI:

| Maturity Tier | Engineering & Verification Requirements |
| :--- | :--- |
| **`Stable`** | Complete implementation; strict static typing (`mypy src` with 0 errors); automated unit + integration test coverage ($\ge 80\%$ module coverage); deterministic execution with seeded RNG; documented in `docs/` and CLI/SDK reference. |
| **`Beta`** | Complete core implementation and passing unit tests; API surface stabilized; edge-case or multi-provider stress testing in progress. |
| **`Alpha`** | Functional prototype with unit tests in mock/stub mode; requires live-credential calibration or multi-environment validation before production reliance. |
| **`Experimental`** | Behind an explicit opt-in flag (e.g., `--enable-llm-judge`); requires calibration governance (`bench calibrate-judge` `GO` verdict) before headline reporting. |
| **`Planned`** | Architectural specification and research anchor defined; scheduled for upcoming release milestone. |

## 4. Long-Term External Hardware & Post-Quantum Horizon

All software-definable evaluation, mechanistic interpretability, zero-knowledge folding, adaptive psychometrics, and regulatory harmonization subsystems have reached **`Stable`** convergence in v1.0. Only external hardware-dependent or post-quantum cryptographic tracks remain on the long-term horizon:

### External Horizon 1 — Physical HSM & Bare-Metal Confidential GPU Attestation Bridge
- **Scope:** Direct hardware driver bindings to physical `/dev/ nitro_enclaves` and NVIDIA H100/B200 Confidential Computing PCIe attestation buses.
- **Target Status:** `Planned` (Requires dedicated bare-metal TEE GPU hardware cluster).

### External Horizon 2 — Post-Quantum LatticeFold Verifiable Evaluation Proofs
- **Scope:** Extend `NovaIVCFolder` with Module-SIS / Ring-LWE lattice folding commitments for post-quantum zero-knowledge auditability.
- **Target Status:** `Planned` (Future cryptographic standard track).
